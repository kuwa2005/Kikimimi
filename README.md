# Kikimimi（聞き耳）

Kikimimi（キキミミ）は、会議に聞き耳を立てるためのアプリです。録音しながら、リアルタイムに文字起こし・アジェンダ（議題）の進行と回答・結論の候補・社内ナレッジの検索を行い、終了後に議事録（要約）を作ります。会員ごとにデータと API キーを分けて使えます。プログラム名は `kikimimi` です。

- 録音はブラウザ（Chrome）が無音の切れ目で区切り（最長 15 秒）、サーバへ送ります。文字起こしは後段の待ち行列で進むため、解析が遅れても録音は止まりません。
- Chrome の音声認識（API キー不要）で書き起こす会議でも、回答・要約用のキー（Claude など）を登録していれば、20 秒ごとに書き起こしの文字をまとめて解析し、事前に置いたアジェンダの各議題へ回答候補を入れます（音声は送りません）。
- 文字起こし・回答候補・要約には、会員が自分で登録した **Gemini** か **OpenAI** の API キーを使います（BYOK）。回答候補と要約は **Claude**（Anthropic）でも作れます。Claude は音声を受け付けないため、その場合も文字起こしには Gemini か OpenAI のキーが要ります。Cursor は外部から呼べる文章生成の API が無いため対応していません。社内ナレッジ（自分でアップロードした資料、運用者が許可したフォルダ、または FESS）は社内で検索し、AI に送るのは短い検索語だけです。
- ログインIDはメールアドレスです。登録は「メールアドレスと招待コード → 6桁の確認コード → パスワード → 利用規約への同意」の順です。暫定の招待コードは `docomo2` です。プランは Free です。このサービスの Free プランと、Gemini / OpenAI / Claude の API 料金・利用枠は別です。

## 起動

### Docker（推奨）

```bash
docker compose up -d --build app
```

`http://127.0.0.1:8765` を Chrome で開きます。登録とパスワード再設定の手順は次のとおりです。確認メールを送るには、下の SMTP の環境変数が必要です。

1. 「新しく登録」でメールアドレスと招待コード `docomo2` を入れる。
2. 届いた6桁の数字を入れる。そろうと次へ進む。
3. ログインパスワードを決める。
4. 利用規約を確認し、「同意して登録」で会員になる。
5. 設定画面で Gemini・OpenAI・Claude の API キーを登録する（Claude のときは、文字起こし用に Gemini か OpenAI のキーも登録する）。

パスワードを忘れた場合は、ログイン画面の「再設定用のメール」から、登録済みのメールアドレスへ確認コードを送れます。未登録のアドレスには送りません。画面の案内は、アドレスが登録済みかどうかで文言を変えません。

データの保存先を変える、またはホストの利用者で動かす場合:

```bash
KIKIMIMI_UID=$(id -u) KIKIMIMI_GID=$(id -g) \
KIKIMIMI_HOST_DATA=$HOME/.local/share/kikimimi \
docker compose up -d --build app
```

開発用（ソースをマウントして `cargo run`）は `docker compose --profile dev up app-dev` です。画面は先に `web/` でビルドしてください（下記「開発」）。

### ローカルで直接

```bash
(cd web && npm ci && npm run build)
cargo run --release
```

Windows では起動すると Chrome がアプリウィンドウで開きます。画面のファイルは `KIKIMIMI_WEB_DIR`、実行ファイルの隣の `web/`、`./web/dist` の順に探します。

## 録音を失わないための仕組み

会議の録音と書き起こしは、次のような事故があっても失わないようにしています（`e2e/` の Playwright 試験で確かめています）。

| 起きること | ふるまい |
|---|---|
| ブラウザが落ちる・タブを閉じる・PC の電源が落ちる | 録音区間と速報字幕は、送る前にブラウザの保管庫（IndexedDB）へ書き、サーバが受け取ってから消します。区切る前の録音も 2 秒ごとに途中保存します。次に開いたときに自動で送ります（失うのは最大 2 秒）。 |
| 回線が切れる・弱い | 録音は止めず、端末に溜めて再送します。つながった瞬間に送ります。長時間のオフラインでも、保存済みの音声はメモリから外して溜めます。 |
| 最初から完全にオフライン | 一度オンラインで開いた端末なら、画面（Service Worker のキャッシュ）を開いて会議を始められます。つながると自動でサーバに会議を作り、録音・書き起こしを送り、録音を続けたまま通常の会議画面へ移ります。オフラインのまま終了した会議は、送り終えてから議事録を作ります。 |
| 別のウィンドウを前面・画面ロック・スクリーンセーバー・省電力 | 録音中は Wake Lock で画面が暗くならないようにします。止められた音声処理は自動で起こし、裏に回る直前にも途中保存します。 |
| マイクが抜ける・ミュートのまま・PC がスリープした | マイクは 10 秒おきに取り直します。ほぼ無音が 15 秒続くとミュートを疑う案内を、音が途切れたときは途切れた秒数を知らせます。 |
| 声が小さい・雑音が多い | 「音声強化」（低い雑音の除去・音量の自動調整）を会議中に切り替えられます。状態が続くと案内します。 |
| API の文字起こしが失敗する | 録音はサーバに残ります。API の会議でも Chrome の速報を控えとして残し、打ち切りになった区間は要約の前に控えで埋めます（議事録に明記）。 |
| 会議が別の端末で終了された・上限に当たった | 届かなかった区間は捨てず、端末に残して会議の録音として取り込み直します。 |
| ログインが切れた | 録音は続け、端末に残します。同じアカウントでログインし直すと送ります。 |
| 電池が少ない・空き容量が少ない | 録音を始めるときと録音中に知らせます。 |

端末にだけ残っている録音は、オフライン会議の画面の「録音を書き出す」で WAV にできます。

## 会員制以前のデータを移す（運用者）

会員制（DB の版 4）に上げると、それまでの会議・テンプレート・資料の索引・共通の設定（API キーを含む）は **持ち主が未設定** になり、誰の画面にも表示されません。最初に登録した人にも自動では見せません。起動時のログに件数が出ます。

移す先の会員が画面から登録したあと、運用者が次を実行します（移す前の DB は `backup/` に自動で残します）。

```bash
docker compose exec app kikimimi admin assign-legacy <ログインID>
```

その他の運用者コマンド:

```bash
kikimimi admin list-users                 # 会員の一覧
kikimimi admin reset-password <ログインID> # 仮パスワードを発行し、その会員のセッションをすべて失効させる
kikimimi admin backup <保存先フォルダ>      # 動かしたまま DB・secret.key・録音・資料を写す
```

パスワードを忘れた場合、ログイン画面から登録済みのメールアドレスへ再設定用の確認コードを送れます。届かないときは、運用者が `reset-password` で仮パスワードを発行し、本人はログイン後にアカウント画面で変更します。

## 環境変数

| 変数 | 既定値 | 内容 |
|---|---|---|
| `KIKIMIMI_DATA_DIR` | OS のデータフォルダ/kikimimi | DB・録音・アップロードした資料・`secret.key` の保存先 |
| `KIKIMIMI_PORT` | 8765（使用中なら 8766〜8774） | 待ち受けポート。指定したときはその番号だけを使う |
| `KIKIMIMI_BIND` | `127.0.0.1` | 待ち受けアドレス。LAN から使うときは `0.0.0.0`（下記の注意を参照） |
| `KIKIMIMI_WEB_DIR` | 実行ファイルの隣の `web` → `./web/dist` | 画面（ビルド済み）の場所 |
| `KIKIMIMI_KNOWLEDGE_ROOT` | なし | 会員が「サーバ上の資料フォルダ」として指定できる範囲（カンマ区切り）。未設定なら指定できない（アップロードだけ） |
| `KIKIMIMI_INVITE_CODE` | 暫定の既定値 | 会員登録に使う招待コード。本番では必ず変えてください |
| `KIKIMIMI_FESS_HOSTS` | なし | 会員が設定できる FESS の接続先（カンマ区切りのホスト名、または ホスト名:ポート）。未設定なら FESS には接続しない（サーバから任意の宛先へ接続させないため） |
| `RUST_LOG` | `kikimimi=info` | ログの詳しさ |
| `KIKIMIMI_GEMINI_BASE` / `KIKIMIMI_OPENAI_BASE` / `KIKIMIMI_ANTHROPIC_BASE` | 各社の API | API の接続先（社内プロキシ経由にするとき・試験の模擬サーバ） |
| `KIKIMIMI_FREE_DAILY_MEETINGS` | 30 | Free の、1日に開始できる会議数（`unlimited` で無制限。日付は `KIKIMIMI_USAGE_UTC_OFFSET`） |
| `KIKIMIMI_FREE_MEETING_MINUTES` | 600 | Free の、1 会議の録音時間（分）。暫定で 10 時間 |
| `KIKIMIMI_FREE_STORAGE_MB` | 1024 | Free の、録音の保存容量（MB） |
| `KIKIMIMI_FREE_CONCURRENT_RECORDINGS` | 1 | Free の、同時に録音できる会議数 |
| `KIKIMIMI_FREE_REALTIME_CAPTIONS` | 1 | Free でリアルタイム文字起こし（速報字幕）を使えるか。上位プランと差別化するときは `0` |
| `KIKIMIMI_ALLOW_CLOUD_SPEECH` | なし | `1` で、速報字幕に Google のサーバ認識（音声が Google に送られる）を選べるようにする。会社の承認を得てから設定する |
| `KIKIMIMI_USAGE_UTC_OFFSET` | `+09:00` | 月の利用量を区切る時差 |
| `KIKIMIMI_SECURE_COOKIE` | なし | `1` でセッション Cookie に Secure を付ける（https で公開するとき） |
| `KIKIMIMI_TRUST_PROXY` | なし | `1` でリバースプロキシの `X-Forwarded-For` / `X-Forwarded-Proto` を信じる |
| `KIKIMIMI_WORKERS` | 2 | 文字起こしを並行して進める区間数（1〜8） |
| `KIKIMIMI_NO_BROWSER` | なし | `1` で起動時に Chrome を開かない |
| `KIKIMIMI_CHROME` | 自動検出 | Chrome の実行ファイル |
| `TZ` | Docker では `Asia/Tokyo` | エクスポートの日時とファイル名に使う地域時刻 |
| `KIKIMIMI_SMTP_HOST` | なし | 登録確認メールの SMTP サーバ。未設定なら確認コードを送れない |
| `KIKIMIMI_SMTP_PORT` | 587（465 のときは暗黙の TLS） | SMTP のポート |
| `KIKIMIMI_SMTP_TLS` | `starttls`（ポート 465 なら `tls`） | `starttls` / `tls` / `none` |
| `KIKIMIMI_SMTP_USER` | なし | SMTP の利用者名。空なら認証しない |
| `KIKIMIMI_SMTP_PASSWORD` | なし | SMTP のパスワード |
| `KIKIMIMI_SMTP_FROM` | なし | 差出人。例: `会議支援 <noreply@example.com>` |
| `KIKIMIMI_MAIL_DIR` | なし | SMTP が無いとき、確認コードをこのフォルダへ書く（動作確認用。公開環境では空のまま） |

SMTP の実値は、リポジトリに含めず `.env` に置きます（`.env.example` はキー名だけです）。`docker compose` は起動時に `.env` を読みます。

Free の上限の既定値は、設計と動作確認のための仮の値です。公開前に運用者が決めてください。

## 使い方の流れ

1. **登録・設定**: メールアドレスと招待コード `docomo2` を入れ、届いた6桁の数字のあとパスワードを決め、利用規約に同意して登録し、設定画面の「AI接続」で Gemini・OpenAI・Claude から選んでキーを登録します（Claude のときは文字起こしに使う Gemini か OpenAI も選びます）。使うモデルは自動で選ばれます。資料をアップロードしたら「索引を作り直す」を押します。
2. **新しい会議**: タイトル・参加者・アジェンダ（議題と目安時間、テンプレートから選択可）を入れ、マイクを選んで「マイクをテスト」で音量を確認します。録音中の文字起こしは「APIで文字起こし」「Chromeのみ（APIキー不要）」「録音だけ」から選びます。APIキーが無い会員の既定は Chrome のみです。「会議開始（録音開始）」で録音を始め、「会議開始（録音一時停止）」なら録音せずに会議を始めます（あとで「再開」や「取り込む…」で録音を足せます）。オンライン会議の相手の声も録る場合は、チェックを入れて会議のタブを「タブの音声も共有する」で共有します。
3. **会議中**: 書き起こし・アジェンダ・関連ナレッジがリアルタイムに更新されます。回答候補には根拠の発言が付き、人が確認した回答は AI に上書きされません。`Ctrl+K`（Mac は `⌘K`）で操作を探せます。
4. **終了**: 「終了」で録音を止めると、残りの文字起こしのあとに要約を作ります。要約に取りかかる前なら終了を取り消せます。
5. **完了後**: 要約の編集・作り直し・コピー、書き起こしの修正、時刻をクリックしての再生、範囲（要約のみ／要約＋回答／記録一式）を選んでの書き出しができます。
6. **アカウント**: プラン（Free）と利用量（今月の会議数・保存容量・同時録音数）、パスワードの変更。

## アジェンダ・関連ナレッジ・聞き手の補助

このアプリは、議事録を取るだけでなく、**顧客へのヒアリングが上手にできる**ことを目指しています。

### アジェンダ（議題）

会議で話し合うこと・相手から聞き出したいことを、進める順に並べたものです。会議の「進行表」として、進行役が会議を回すのを助けます。件数に上限はありません。

- **目安時間**: 議題ごとに目安（分）を入れられます（任意）。会議中は、議題ごとの経過時間（いまの議題として話していた録音時間）と目安を並べ、超えたら色で知らせます。上部に「完了 n / 全 m 件」「経過 / 目安の合計（残り）」を出します。
- **いまの議題**: AI が発言から話題になっている議題を判定します。人が「この議題へ」で切り替えることもできます。「完了して次へ」で、いまの議題を完了にして次の議題へ進みます。人が完了にした議題へ AI が勝手に戻すことはありません。
- **回答・結論**: AI が発言から議題ごとの回答・結論の候補を作り、未着手 → 途中 → 完了 と進めます。候補には根拠の発言（時刻）が付き、押すとその発言へ移れます。
- **AI が足す・外す**: 話の流れから確かめるべき事項が出てくると「AI が追加」として足します（1 会議 5 件まで）。発言で不要とはっきりしたものは「AI が不要と判断: 理由」として外します。どちらもワンクリックで戻せます。
- **今回は扱わない**: この会議では扱わない議題を外すボタンです。外したものは一覧の下にまとまり、AI の更新の対象から外れます。
- **終了するとき**: まだ終わっていない議題があれば、終える前に一覧で知らせます（聞き漏らしチェック）。
- **議事録**: 議題ごとの結論・目安・経過を残し、終わらなかった議題は「次回確認すること」として残します。
- 空のままでも始められます。その場合は全文から要約を作り、話の流れから AI が議題を足します。

### 関連ナレッジ

アップロードした社内資料（設定の「ローカル資料」）、運用者が許可したフォルダ、または FESS から、**会話に合う資料を自動で探して出す**機能です。

- **会議中**: 発言から AI が短い検索語を作り、その場で資料を探します。いまの議題が変わったときは、その議題の文でも探します。見つかった資料は「アジェンダ」の下の「いまの話題の資料」に自動で出ます。資料パネル・タブにも新着の件数を表示します。
- **何に役立つか**: 価格表・仕様・過去の提案・社内規程などを、会話を止めずにその場で確かめられます。顧客の質問に、根拠のある答えをすぐ返せます。
- **ピン留め**: 使った資料をピン留めすると、議事録の「参照した社内ナレッジ」に残り、要約でも根拠として扱います。
- 資料の本文は AI に送りません。送るのは短い検索語だけです。資料が未登録のときは、自動では何も出ません。

### 顧客資料

顧客から受け取った資料（PDF・Word の .docx・Excel の .xlsx・テキスト）を、会議ごとに添付できます（資料パネルの「＋ 顧客資料を添付」）。

- 添付すると本文を取り出して索引し、会話から作った検索語・いまの議題で、**その会議の中だけで**自動で探して「顧客資料」として出します。社内資料と区別して表示します。
- Excel はシートごと・行ごとに、セルを「 | 」でつないで読みます（数式のセルは保存されている値）。Word は段落と表を読みます。
- 使った箇所をピン留めすると、議事録の「参照した資料」に残り、要約でも根拠として扱います。
- 原本は会議の持ち主だけが取り出せ、会議を消すと一緒に消えます。1 会議 20 件・1 件 8MB まで。
- 旧形式の .doc / .xls は中身を確実に読めないため受け付けません。docx / xlsx か PDF で保存し直してください。
- 設定の「ローカル資料」（社内資料）も .docx / .xlsx を受け付けます。

### 聞き手の補助（会議中）

キーボードを打たずに、クリックだけで使えるようにしています。

| 機能 | 内容 |
|---|---|
| 次に聞くと良い | 話の流れとまだ終わっていない議題から、次に投げかけるとよい問いかけを 1 つ出す（切り口: 具体化・理由・数字・期限・決裁者・影響・次の一歩） |
| メモ | 決定事項・宿題（誰が・何を・いつまで）・数字や日付・懸念・用語の説明を、発言から自動で拾う。誤りは × で消せる。議事録の材料になる |
| ★ ここ重要 | 押した時刻の発言に印を付け、議事録で重視させる |
| ここまでの要点 | 直近 10 分ほどの流れを 3 行にまとめる（聞き逃したとき、途中から加わった人への説明に） |

用語の説明は AI の一般知識によるもので、社内資料とは区別して表示します。

## リアルタイム文字起こし（速報字幕）

設定の「リアルタイム文字起こし（速報字幕）」を ON にすると、録音中に Chrome の音声認識で、話した内容を 1 秒ほどで書き起こし欄の末尾に薄く出します。

- 正式な書き起こし・回答・メモ・要約は、これまでどおり区間ごとの AI の文字起こしで作ります。AI の書き起こしが届いた部分の速報は置き換わります。速報は保存しません。
- 既定は**端末内の認識**だけです（音声は端末の外に出ません）。日本語の言語パックが無い端末では、設定画面から入れられます。「この端末で使えるか確認」で確かめられます。
- Google のサーバで認識する方式は、運用者が `KIKIMIMI_ALLOW_CLOUD_SPEECH=1` を設定した場合だけ選べます（音声が Google に送られるため、会社の承認が要ります）。
- 録音と同じ音（マイク＋共有したタブの音声）を認識します。議題と参加者名を、当てやすくする語として渡します。
- デスクトップの Chrome だけで動きます。対応していないブラウザ・端末では使えない旨を表示します。
- **プランでの差別化**: プランの機能 `realtime_captions` で使えるかを決めます。いまは Free でも使えます。上位プランを始めたら `KIKIMIMI_FREE_REALTIME_CAPTIONS=0` にします（アカウント画面に使える機能を表示します）。

## ボイスレコーダーの録音・書き起こしの取り込み

ノート PC を机に置いたまま現場で話を聞いた場合でも、その間の話を 1 本の議事録につなげられます。

- 会議の画面の「取り込む…」から、音声ファイル（mp3・m4a・wav・ogg など Chrome が読める形式）か、文字起こし済みのテキスト（txt・vtt・srt）を選びます。
- **置く位置**: 「続きとして末尾に足す」か「開始時刻に合わせて差し込む」を選べます。音声は、ファイルの日時（多くのレコーダーは録音を終えた時刻を残します）から開始時刻を推定して入れます。既存の録音と重なる位置には入れません。
- 音声はブラウザで 16kHz・モノラルに変換し、会議中の録音と同じく区間に分けて送ります。文字起こし・回答候補・メモ・資料の検索・要約が、ライブの録音と同じように動きます。
- テキストは時刻（vtt・srt のキュー、行頭の `[00:12]` など）があればその時刻で、無ければ段落ごとに並べます。取り込んだ文からも回答候補とメモを作ります。
- 完了済みの会議にも取り込めます。取り込みの処理が終わると、要約を作り直します。
- PC で録音しなかった場合は、新しい会議の画面の「録音せずにファイルから作る」で、取り込みだけの会議を作れます。
- Free プランの上限（1 会議の録音時間・保存容量）は、ライブの録音と同じく数えます。

## フォルダと並び順

- ホームの「これまでの会議」は、フォルダで分けられます（「＋ フォルダ」で追加、名前の変更・削除）。フォルダを削除しても、中の会議は「フォルダなし」に戻るだけで消えません。
- 会議の行の ⋮⋮ をドラッグすると並べ替え、フォルダの上へドラッグするとフォルダへ移せます（⋮⋮ にフォーカスして ↑↓ キーでも並べ替えられます）。
- フォルダを選ぶと「まとめてダウンロード（ZIP）」で、フォルダ内の議事録（下書きを除く）を会議ごとの Markdown にまとめて取り出せます。
- フォルダを開いた状態で「新しい会議」を押すと、そのフォルダに入ります。

## LAN の別端末から使う

### マイクには https が必要です

ブラウザは `http://127.0.0.1` / `http://localhost` 以外の **http** の画面ではマイクを使わせません。別端末から録音する場合は、TLS 終端のリバースプロキシを前に置き、`KIKIMIMI_SECURE_COOKIE=1` と `KIKIMIMI_TRUST_PROXY=1` を設定してください。例（Caddy、社内 CA の証明書を自動発行）:

```
# Caddyfile
kikimimi.example.local {
    tls internal
    reverse_proxy 127.0.0.1:8765
}
```

`tls internal` の場合は、Caddy のルート証明書を各端末に信頼させる必要があります。証明書の秘密鍵は認証情報として扱い、リポジトリに含めないでください。

### 公開するときの注意

- 会員登録には暫定の招待コードが必要です。確認コードの送信は、IP ごとに 1 時間 10 件、メールアドレスごとに 1 時間 5 件、全体で 1 時間 200 件までです。インターネットに公開せず、信頼できる社内ネットワークで使ってください。
- 会員の API キーと FESS トークンは、データフォルダの `secret.key` で暗号化して DB に保存します（XChaCha20-Poly1305）。暗号文は「会員ID＋項目名」に結び付けてあり、別の会員の行や別の項目へ写しても復号できません。画面や API にはキーの値を返しません。
- `secret.key` を失うとキーを読めなくなり、DB と一緒に漏れるとキーを復号できます。権限を利用者だけにし、DB とは別に保管してください。
- キーをブラウザ側だけに持たせる方式は採っていません。会議の終了後の自動要約や混雑時の再試行は、ブラウザを閉じたあとにもサーバで動くため、サーバがキーを使える必要があるからです。
- パスワードは Argon2id で保存し、セッションは HttpOnly の Cookie と CSRF トークンで守ります。ログインは ID ごと・IP ごとに試行回数を制限しています。

## データとバックアップ

データフォルダには次のものがあります。

- `kikimimi.sqlite`（と `-wal` / `-shm`）: 会員・会議・書き起こし・要約・設定
- `audio/<会議ID>/<開始ミリ秒>.wav`: 録音の区間ファイル（16kHz / モノラル / 16bit）
- `knowledge/<会員ID>/`: 会員がアップロードした資料
- `meeting_docs/<会議ID>/`: 会議に添付した顧客資料の原本
- `secret.key`: 秘密値の暗号鍵
- `backup/`: 自動で残したバックアップ（DB の版を上げる前、`assign-legacy` の前）

バックアップは、動かしたまま次のコマンドで取れます。DB の一貫した写し・`secret.key`・録音・資料を、日時付きのフォルダへ写します。サーバを止めてからフォルダごとコピーしても構いません。

```bash
docker compose exec app kikimimi admin backup /data/backup
```

`secret.key` を失うと、保存した API キーを読めなくなります。DB と一緒に、外に漏れない場所へ保管してください。スキーマは起動時に自動で最新版へ移行し、版を上げる前の DB を `backup/` に残します。

## 開発

```bash
cargo test              # サーバ（Rust）
(cd web && npm ci && npm run build)   # 画面（型検査とビルド）
```

Rust や Node が無い環境では、Docker で実行できます。

```bash
docker build --target dev -t kikimimi-dev .
docker run --rm -v "$PWD":/app -v kikimimi-target:/app/target -w /app kikimimi-dev cargo test
docker run --rm -v "$PWD/web":/web -w /web node:22-alpine sh -c "npm ci && npm run build"
```

- サーバ: Rust / Axum / SQLite（`src/`）。API の取り決めは `docs/api.md`。
- 画面: React 19 + TypeScript + Vite 8（`web/`）。録音（AudioContext・無音判定・送信キュー）は React の外のモジュール（`web/src/recorder/`）にあり、画面の再描画で止まらない。
- Docker イメージは画面をビルドして同梱するので、変更後はコンテナを作り直してから確認してください。
