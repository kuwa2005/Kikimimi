# 実機での確認手順（QA チェックリスト）

目標の 4 つの柱（確実な録音保存・即座の開始・確実な取得と文字起こし・使い勝手）ごとに、実機で行う手順と、合否の基準をまとめます。
自動試験（`e2e/resilience.mjs`、Playwright＋偽マイク）で確かめている項目は「e2e」の列にシナリオ名を書きます。`—` は自動試験が無く、実機でしか確かめられない項目です。

## 準備

- 端末: Windows または Mac の Chrome（PC）、Android の Chrome（ブラウザと、ホーム画面に追加したアプリ）、iPhone の Safari（ブラウザと、ホーム画面に追加したアプリ）。
- 接続: 別端末からは https が必要です（README「LAN の別端末から使う」）。試験用のアカウントで行い、本番の会議データは使いません。
- 回線を悪くする方法: 機内モード（完全に切る）、PC の Chrome DevTools の Network「Offline」「Slow 3G」、Wi‑Fi の電波が届きにくい場所（つながっているのに応答が無い状態）。
- 時間の測り方: 別の端末のストップウォッチで画面を撮影するか、声で「スタート」と言ってから録音の再生で確かめます。
- 結果の確かめ方: 会議の完了後に、録音を最初から再生し、書き起こしと照らし合わせます。区間の隙間・重なりは e2e と同じく、サーバの録音区間の並び（`audio_jobs` の `start_ms` と長さ）で確かめられます。

## 1. 確実な録音保存（録音を失わない）

| # | 手順 | 合格の基準 | e2e |
|---|---|---|---|
| 1-1 | 録音中に機内モードにして 20 秒待ち、戻す | 録音が止まらない（経過時間が進み続ける）。復帰後 30 秒以内に送信待ちが 0 になる。再生して 20 秒の間に音の欠けが無い | `offline` |
| 1-2 | 応答の無い回線（電波の弱い場所・DevTools の Slow 3G）で 5 分録音する | 録音が止まらない。回線が戻ったあと、全区間がサーバに届く | `errors`（500 応答で代用） |
| 1-3 | 録音中に未送信がある状態でブラウザを強制終了し、開き直す | 次に開いたとき自動で送られる。失うのは最後の 2 秒以内 | `crash` |
| 1-4 | 1-3 の直後、復元を待たずに「録音を再開」を押す | 前の録音と再開後の録音が隙間・重なりなく並ぶ | `crashresume` |
| 1-5 | 完全オフラインで録音中にブラウザを強制終了し、オフラインのまま開き直して終了 → 回線を戻す | ホームに端末の会議が出る。回線が戻ると会議が作られ、落ちる直前までの録音が残る | `offlinecrash` |
| 1-6 | PC: 録音中に別ウィンドウを前面にする・画面をロックする・スリープから戻す | 録音が続く。スリープした場合は、途切れた秒数が案内される | `background`（スリープは —） |
| 1-7 | 録音中に USB／Bluetooth マイクを抜いて挿し直す | 10 秒以内にマイクを取り直す。案内が出る | `background`（切断のみ） |
| 1-8 | 送れない間に別の端末で同じ会議を終了する | 届かなかった区間が捨てられず、取り込みとして保存される | `errors` |
| 1-9 | 同じ会議を 2 つのタブで録音しようとする | 2 つ目のタブは録音を始めず理由を出す。1 つ目は続く | `twotabs` |
| 1-10 | iPhone: 録音中に電源ボタンで画面を消し、10 秒後に戻る | 録音が止まることを確認する（制限）。止まるまでの録音が残っている。録音開始時に iOS の注意が出ている | — |

## 2. 即座の開始

| # | 手順 | 合格の基準 | e2e |
|---|---|---|---|
| 2-1 | ホーム画面のアイコンから起動し、「すぐ録音」を押して録音中になるまでを測る（オンライン） | 起動後の操作は **1 タップ**。押してから録音中の表示まで **2 秒以内**（初回のマイク許可を除く） | — |
| 2-2 | Android: アイコン長押しのショートカット「すぐ録音」から起動 | 起動後の操作は **0 タップ**で録音が始まる。止まる場合は「画面のどこかを 1 回タップ」の案内が出て、1 タップで始まる | — |
| 2-3 | 応答の無い回線（つながっているのに返事が来ない）で「すぐ録音」を押す | 多くは約 4 秒でオフライン開始に切り替わり（設定・作成・開始の各 API がそれぞれ 4 秒近くかかった場合でも最長約 12 秒）、録音が止まらない。回線が戻るとサーバの会議に引き継がれ、録音が隙間なく 1 つの会議に並ぶ | `offlinestart`（完全オフラインのみ。応答の無い回線は —） |
| 2-4 | 機内モードで画面を開き直し、「すぐ録音」を押す（一度オンラインで開いた端末） | 画面が開き、録音が始まる。回線が戻ると自動で引き継がれる | `offlinestart` |
| 2-5 | 押すと同時に「いち、に、さん」と話し始める（オンライン・弱い回線の両方） | 録音の先頭に「いち」から残っている（プリロール） | — |
| 2-6 | 新しい会議の画面で「マイクをテスト」中に話し、そのまま「会議開始（録音開始）」を押す | 押す直前の最大約 4 秒が録音の先頭に残る | — |
| 2-7 | ページを開いた直後、画面に一度も触れずに PWA ショートカットから開始する（自動再生の制限） | 約 1.5 秒で「タップすると録音が始まります」の案内が出て、1 タップで録音が始まる。「開始しています…」のまま止まらない | — |
| 2-8 | 前の会議で「タブの音声も共有する」を使ったあと、PC で「すぐ録音」を押す | 画面共有の選択が出ず、マイクだけで始まる | — |

## 3. 確実な取得と文字起こし

| # | 手順 | 合格の基準 | e2e |
|---|---|---|---|
| 3-1 | 声の小さいマイク・離れた位置で、会議中に「音声強化」をオン・オフ | オンで声の大きさが上がり、録音は止まらない | `enhance` |
| 3-2 | マイクをミュートのまま録音を始める | 15 秒以内にミュートを疑う案内が出る | — |
| 3-3 | Android Chrome（ブラウザと PWA の両方）で Chrome の音声認識の会議を 5 分行う | 速報字幕が出続ける。途中で回線を 10 秒切っても、つなぎ直して字幕が続く | `capnet`（PC の Chromium） |
| 3-4 | iPhone Safari で Chrome の音声認識の会議を始める | 速報字幕が使えない場合は、録音は続き、理由（Android／PC の Chrome を使う・API の文字起こしを選べる）が表示される | — |
| 3-5 | API の文字起こしでキーを無効にして会議を行う | 失敗区間が速報字幕の控えで埋まり、議事録に欠落と補完が明記される | `apifail` |
| 3-6 | Chrome の書き起こしの会議を終え、全文の再生で時刻を確かめる | 各行の時刻が発言の始まりに合う | `timing` |
| 3-7 | アジェンダを置いた会議で、関係する発言と関係しない発言をする | 関係する議題にだけ回答候補が入る | `agenda` |

## 4. 使い勝手

| # | 手順 | 合格の基準 | e2e |
|---|---|---|---|
| 4-1 | iPhone・Android で「ホーム画面に追加」して開く | アドレスバーの無い画面（standalone）で開き、アイコンと名前「聞き耳」が出る | — |
| 4-2 | iPhone: Safari で開いた場合と、ホーム画面のアプリで開いた場合を比べる | どちらでも録音できる。マイクの許可を聞かれる回数、画面が暗くならないか、iOS の注意の文言（ブラウザのときだけ「ホーム画面に追加」を勧める）を記録する | — |
| 4-3 | スマートフォンで録音中に下へスクロールする | 画面下の操作（録音中・経過時間・一時停止・終了）が常に見え、片手の親指で押せる | — |
| 4-4 | 「すぐ録音」で始めた会議に、録音中にタイトル・参加者・議題を足す | 録音を止めずに編集できる | — |
| 4-5 | 「すぐ録音」を素早く 2 回押す | 会議は 1 つだけ作られる | — |
| 4-6 | 録音中に一時停止 → 送信待ちのダイアログで「操作をやめる」 | 録音が続く | `cancelpause` |
| 4-7 | 会議中に字幕の並び順を切り替える | 新しい字幕が上になり、録音は止まらない。設定が端末に残る | `order` |

## 記録の残し方

端末・OS とブラウザの版・起動方法（ブラウザ／ホーム画面のアプリ）・回線の状態・手順の番号・合否・かかった秒数とタップ数を残します。不合格のときは、画面の案内の文言と、会議の番号を書きます。録音そのものや顧客の会話は記録に貼らないでください。

## 自動試験で確かめていないこと

次は `e2e/resilience.mjs` にシナリオが無く、上の表の「—」の手順で確かめます。

- 「すぐ録音」の導線（ホームのボタン、PWA ショートカット `?quick=1`）。e2e の `startMeeting` は「新しい会議」画面の「会議開始（録音開始）」を使っています。
- 開始系 API の約 4 秒のタイムアウトによるオフライン開始への切り替え（応答の無い回線）。`offlinestart` は完全オフラインだけを試しています。
- プリロール（開始前の最大約 4 秒）が録音の先頭に入ること。
- 自動再生の制限でのタップ待ち（約 1.5 秒）と、iOS の注意の表示。
- iOS・Android の実機でのふるまい（画面ロック、PWA と標準ブラウザの差、Android の速報字幕）。
